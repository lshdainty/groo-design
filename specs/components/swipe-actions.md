# Swipe Actions

> 폰(768 미만) 목록 줄을 왼쪽으로 밀면 오른쪽에서 동작 버튼이 드러나는 지름길입니다. 줄을 열어 상세로 들어가지 않고도 수정 · 삭제 같은 잦은 동작에 바로 닿습니다. iOS 메일 · 메시지의 스와이프와 같은 동작입니다. 같은 동작은 늘 줄을 눌러 들어간 화면에도 있고, 줄 끝 ⋮ 는 두지 않습니다([Menu](menu.md) 의 "줄의 동작").

미는 지름길을 남기되, 같은 동작은 줄을 눌러 들어간 화면에 모두 둡니다 — 끌기 같은 제스처에는 단순한 누르기로 닿는 대체 길이 있어야 하기 때문입니다(기초 Inclusive Design).

줄 자체를 다시 만들지 않습니다 — **기존 줄을 감싸는 컨테이너**입니다. 줄의 모양 · 누르기는 그대로 두고 뒤에 동작 트레이를 붙입니다. 그래서 거래 줄이든 할 일 줄이든 감싸기만 하면 같은 제스처를 얻습니다. **동작은 고정 목록이 아닙니다** — 항목마다 할 수 있는 일이 달라서(문자함은 수정이 없고, 메모는 고정이 있습니다) 부르는 쪽이 1 ~ 3개를 조립합니다. 스펙은 동작의 모양과 배치를 정하고, 무엇을 넣을지는 정하지 않습니다.

수치 원본은 [`swipe-actions.yaml`](swipe-actions.yaml)입니다.

## Anatomy

[그림: 줄을 왼쪽으로 밀면 뒤에서 동작 칸(원형 배지 + 라벨)이 드러납니다 — 첫 칸 앞 20 · 칸 사이 12, 마지막 칸은 화면 끝에](../../site/components/specs/swipe-actions.tsx#anatomy)

| ⓐ Row | 감싸는 목록 줄입니다 — 높이 · 여백 · 바탕 모두 원래 줄의 것입니다. 다만 높이가 56 보다 낮으면 56 입니다 — 트레이 칸(배지 36 + 2 + 라벨 15.6)이 들어가야 하기 때문입니다. 글자가 커져 칸 내용이 더 높으면 그만큼 높아집니다(웹은 넘친 칸을 잘라 숨기지 않습니다 — 웹 · 앱이 같습니다). 미는 동안 `translateX(−N)` 만 받습니다. 닫혔을 때 초점을 받을 수 있습니다(`Esc` 로 돌아올 자리). |
| ⓑ Track | 줄 뒤에 드러나는 자리입니다 — 바탕을 칠하지 않습니다. 색을 깔면 줄 옆에 상자가 하나 더 생긴 것처럼 보입니다. |
| ⓒ Action | 동작 한 칸입니다 — 원형 배지 + 그 아래 라벨, 세로 가운데. 누르는 자리는 칸 전체입니다. |

## Properties

### Kinds

동작은 셋입니다 — 곁 동작(`neutral` — 고정 · 보관 · 공유), 주 동작(`primary` — 수정), 되돌리기 어려운 동작(`destructive` — 삭제). 색은 원형 배지만 갖고 트레이는 칠하지 않습니다.

- **배지는 그 동작의 글자색으로 채우고 아이콘은 반전 글자입니다** — `primary` 는 `fg-informative`, `destructive` 는 `fg-critical`, 아이콘은 `fg-neutral-inverted`. 라이트는 짙은 배지 + 흰 아이콘, 다크는 밝은 배지 + 짙은 아이콘이라 두 모드 모두 배지가 줄 바탕과 3:1 을 넘습니다(라이트 5.06 · 5.09 · 다크 6.08 · 6.12). 다크에서 짙은 채움(`bg-critical-solid` · `bg-informative-solid`)을 그대로 쓰면 줄 바탕과 2.51 입니다.
- **`neutral` 배지는 옅은 바탕(`bg-neutral-weak`) + 안쪽 1px `stroke-neutral-weak`** 입니다 — 바탕만으로는 줄과 1.08 · 다크 1.30 이라 둘레를 테두리로 잡습니다. 아이콘 `fg-neutral`(15.20 · 10.32)과 라벨이 동작을 알립니다.
- **라벨은 배지 밖이라 본문 색입니다** — `neutral` · `primary` 는 `fg-neutral-muted`, `destructive` 만 `fg-critical`(라이트 · 다크 한 토큰). 주 동작의 라벨을 파랑으로 칠하지 않습니다 — 색은 배지가 알립니다.

`destructive` 는 **가장 안쪽(화면에서 가장 왼쪽)** 에 둡니다 — 조금만 밀면 바깥쪽 동작부터 드러나므로, 파괴적인 것을 바깥에 두면 제일 먼저 손에 닿기 때문입니다. 부르는 쪽은 `[고정, 수정, 삭제]` 처럼 **뜻의 차례 그대로** 넘기고, 그리는 쪽이 뒤집습니다.

### Size

동작 칸은 크기가 하나입니다. 높이는 줄을 따릅니다.

- **배지 36 · 아이콘 18** — 줄 높이 안에 원과 라벨이 함께 들어가는 최대치입니다. 40 은 라벨과 합쳐 넘칩니다.
- **간격은 배지 앞에만** 둡니다 — 첫 칸 앞 20, 칸 사이 12. 뒤에도 두면 마지막 배지와 화면 끝이 벌어져 덜 열린 것처럼 보입니다. 마지막 칸은 화면 끝에 붙습니다 — 칸 폭은 첫 칸 56 · 다음부터 48, 트레이는 하나 56 · 둘 104 · 셋 152 입니다.
- **높이는 줄을 따르되 56 보다 낮으면 56** 입니다 — 누르는 자리는 배지(36)가 아니라 칸 전체(48 ~ 56 × 줄 높이)입니다.
- **배지↔라벨 gap 2** — 배지 아래 라벨까지 한 덩어리로 읽히게 붙입니다.
- **라벨 12 / 700 / 1.3** — 크기만 `t2` 이고 굵기 · 줄 높이는 이 컴포넌트의 값입니다. 따로 적은 값이 `t2` 의 굵기 · 줄 높이를 덮습니다(스펙 JSON 은 12 / 15.6 · 700 하나로 접어 싣습니다). 칸 폭 48 이 좁아 기본 줄 높이(16)면 두 줄에서 넘칩니다. 굵기는 버튼 글자와 같은 700 이고, 600 은 쓰지 않습니다.
- 사각 채움이 아니라 원형인 이유 — 줄을 밀었을 때 색 덩어리가 화면을 반 가르지 않고 아이콘만 또렷하게 서기 때문입니다.

### State

| 상태 | 모습 |
|---|---|
| `enabled` | 배지 색 그대로 |
| `hovered` | 웹 — 누름과 같은 모습(밝기 88%) |
| `pressed` | 배지 · 라벨 밝기 88% — 움직이지(축소 · 이동) 않습니다. 손가락으로 밀어 둔 트레이와 이중으로 움직이면 어지럽기 때문입니다 |
| `focused` | 키보드 포커스에만 칸 안쪽 2px 링 — 트레이 바깥으로 나가면 줄 경계에서 잘립니다 |

## Guidelines

### 지름길입니다 — 같은 동작은 들어간 화면에

미는 법을 모르는 사람 · 키보드 · 스크린리더는 줄을 눌러 한 단계 들어간 화면(상세 · 수정)에서 같은 동작에 닿습니다 — 동작이 하나(삭제)면 바닥 왼쪽 [삭제](`ghost` + `critical`), 여럿이면 머리 오른쪽 ⋮ → [Menu Sheet](menu-sheet.md)([Menu](menu.md) 의 "줄의 동작")입니다. 트레이와 들어간 화면은 같은 동작 · 같은 이름 · 같은 확인창입니다. 트레이에 있는 동작은 모두 들어간 화면에도 둡니다 — 스와이프로만 닿는 동작을 만들지 않습니다. 줄 끝 ⋮ 는 두지 않습니다.

[그림: 같은 동작 — 밀어 연 트레이 · 줄을 눌러 들어간 화면의 머리 ⋮](../../site/components/specs/swipe-actions.tsx#more-guide)

### 동작은 하나에서 셋까지

넷부터는 트레이가 줄 폭을 먹어 무엇을 미는지 안 보입니다 — 자주 쓰는 셋까지만 트레이에 두고, 나머지는 들어간 화면에만 둡니다. 파괴적 동작은 하나만, 가장 안쪽에 둡니다.

[그림: 동작 둘 · 넷을 늘어놓은 트레이](../../site/components/specs/swipe-actions.tsx#count-guide)

### 파괴적 동작은 확인을 받습니다

`destructive` 는 누른 즉시 실행하지 않고 확인 창([Alert Dialog](alert-dialog.md))을 띄웁니다 — 스와이프가 삭제까지의 거리를 줄이는 만큼, 줄어든 만큼을 확인 단계로 되돌려 놓습니다. 트레이를 **먼저 닫고** 나서 띄웁니다 — 열어 둔 채 띄우면 취소하고 돌아왔을 때 그대로 열려 있고, 실행한 경우엔 사라진 줄 자리에 트레이만 남습니다.

**확인 창의 제목 · 설명은 상세 경로와 같은 문구입니다** — 같은 계좌를 상세에서 지우든 밀어서 지우든 "계좌 삭제" 입니다. 결과가 같은 동작이 길에 따라 다른 말로 뜨면 사람은 그것을 다른 일로 읽습니다. 이 컴포넌트는 감싼 줄이 무엇인지 모르므로 **문구는 그 줄을 아는 부르는 쪽이 넘깁니다**. 확인 버튼은 누른 동작의 라벨 그대로입니다(`삭제` 를 눌렀으면 확인도 `삭제`) — 방금 누른 버튼의 연장이라 길과 상관없이 같습니다. 들어간 화면의 [삭제] · 머리 ⋮ → Menu Sheet 로 지울 때도 같은 확인 창입니다.

[그림: 삭제 — 트레이가 닫히고 상세와 같은 확인 창("계좌 삭제")](../../site/components/specs/swipe-actions.tsx#confirm-guide)

### 끝까지 밀어도 실행하지 않습니다

끝까지 밀어 바로 지우는 방식은 되돌리기가 있을 때만 맞는데, 여기엔 되돌리기가 없습니다 — 밀다가 손이 미끄러져 지워지는 것보다 한 번 더 누르는 게 낫습니다. 끝까지 밀어도 트레이가 열릴 뿐입니다.

### 제스처 판정

목록에서 주 동작은 **세로 스크롤**입니다. 가로 제스처는 세로를 방해하지 않는 선에서만 가져갑니다.

| 항목 | 값 | 이유 |
|---|---|---|
| 데드존 | 8px | 이보다 짧은 이동은 누르기로 봅니다. 축을 판정하지 않습니다. |
| 축 확정 | `abs(dx) > abs(dy) × 1.5`(≈ 33.7° 이내) | 45°(1배)로 잡으면 세로로 훑는 중 손가락이 조금만 기울어도 스크롤이 끊깁니다. |
| 세로 스크롤 | `touch-action: pan-y` 로 **브라우저에 남깁니다** | `preventDefault` 로 직접 처리하지 않습니다 — 관성 · 튕김이 OS 것과 달라집니다. |
| 미는 동안 | 글 고르기 · 길게 누름 메뉴 막음 | 가로로 미는 동안 선택 손잡이 · 메뉴가 뜨면 제스처가 죽습니다. |
| 열기 | 트레이 폭의 **40%** 이상 밀고 놓으면 열린 채로 | 2개 트레이(104)면 41.6 |
| 닫기 | 열린 채 되돌려 민 거리가 트레이 폭의 **25%** 이상 | 여는 문턱(40%)을 닫는 쪽에 같이 걸면 두 범위가 맞물려 아예 열리지 않습니다 |

세로로 확정된 제스처는 손을 뗄 때까지 가로로 되돌리지 않습니다 — 판정이 도중에 바뀌면 줄이 스크롤 중에 흔들리기 때문입니다.

### 폰 전용

데스크톱에서는 트레이를 쓰지 않습니다 — 마우스로 줄을 미는 건 익숙한 동작이 아니고, 넓은 화면에서도 줄을 누르면 들어간 화면에서 동작을 고릅니다([Menu](menu.md) 의 "줄의 동작"). 판정은 뷰포트 폭이다(768 미만) — 포인터 종류(`pointer: coarse`)로 가르지 않습니다(터치 노트북이 데스크톱 화면에서 스와이프를 갖게 됩니다). 768 이상에서는 감싸기를 걷어내 줄을 그대로 통과시킵니다.

| | 폰(768 미만) | 768 이상 |
|---|---|---|
| 트레이 | 밀어서 연다 | 없음 — 줄만 |
| 동작에 닿는 길 | 밀기(지름길) · 줄 누르기 → 들어간 화면 | 줄 누르기 → 들어간 화면 |
| 줄 누르기 | 상세 — 동작 하나면 바닥 [삭제], 여럿이면 머리 ⋮ → Menu Sheet | 상세 — 머리 ⋮ 는 1280 미만 Menu Sheet · 이상 Menu |

[그림: 폰은 트레이 · 데스크톱은 줄만 — 둘 다 줄을 누르면 들어갑니다](../../site/components/specs/swipe-actions.tsx#platform-guide)

### RTL

미는 방향이 뒤집힙니다 — RTL 에서는 **오른쪽으로** 밀고 트레이가 **왼쪽**에서 나옵니다. `translateX` 부호와 트레이 정렬을 `:dir(rtl)` 로 가릅니다. 동작 차례는 그대로입니다(가장 파괴적인 것이 손가락이 끝까지 간 쪽).

### 글

라벨은 동사로 짧게 씁니다 — 한글 두 글자("수정" · "삭제" · "고정"). 글이 배지보다 넓으면(영어 "Delete" · 큰 글자) 칸이 글 폭만큼 넓어집니다 — 글이 넘치거나 줄 높이를 넘지 않습니다. 동작의 이름은 "라벨: 줄 제목"("삭제: 다라커피")입니다.

## 코드

레시피 `recipes/shadcn/components/ui/swipe-actions.tsx` 를 씁니다. 아래 미리보기는 스펙 값으로 그린 모습입니다.

- `SwipeActions` — 줄을 감쌉니다. `actions`(1 ~ 3개 — `{ kind, label, icon, disabled, onSelect }`, 뜻의 차례로) · `enabled`(폰일 때만 `true` — 768 이상이면 `false` 로 넘겨 줄만 그립니다) · `rowLabel`(동작 이름에 붙는 줄 제목 — "삭제: 다라커피")을 받습니다. 동작을 누르면 트레이를 닫은 뒤 `onSelect` 를 부릅니다. 감싼 줄은 `tabIndex={-1}` 로 초점을 받을 수 있고, 열린 트레이를 `Esc` 로 닫으면 초점을 줄로 옮깁니다.
- 한 번에 한 줄만 열리기 · 스크롤하면 닫히기는 목록의 조상(`SwipeActionsProvider`)이 맡습니다 — 줄 하나는 다른 줄의 상태를 모릅니다.

### 가계부 줄

[그림: 거래 줄 — 밀면 수정 · 삭제, 누르면 상세](../../site/components/specs/swipe-actions.tsx#ex-row)

```tsx
import { Pencil, Trash2 } from "lucide-react"
import { ListButtonItem } from "@/components/ui/list"
import { SwipeActions, type SwipeAction } from "@/components/ui/swipe-actions"

const actions: SwipeAction[] = [
  { kind: "primary", label: "수정", icon: <Pencil />, onSelect: () => edit(tx) },
  // 확인 창은 상세에서 지울 때와 같은 문구 — 부르는 쪽이 넘긴다
  { kind: "destructive", label: "삭제", icon: <Trash2 />, onSelect: () => confirmDelete({ title: "거래 삭제", description: `${tx.title} 거래를 지울까요?` }) },
]

<SwipeActions actions={actions} enabled={isPhone} rowLabel={tx.title}>
  <ListButtonItem
    prefix={<CategoryTile category={tx.category} />}
    title={tx.title}
    detail={tx.meta}
    suffix={<Amount value={tx.amount} />}
    /* 줄 끝 ⋮ 는 두지 않는다 — 같은 수정 · 삭제는 상세에 있다(키보드 · 스크린리더의 길) */
    onClick={() => openDetail(tx)}
  />
</SwipeActions>
```

## Behavior

| 상황 | 동작 |
|---|---|
| 왼쪽으로 끌기 | 줄이 손가락을 따라갑니다. 최대 이동 = 칸 폭의 합(56 · 104 · 152) — 더 밀어도 움직이지 않습니다 |
| 놓음 — 트레이 폭의 40% 미만 | 닫힙니다 |
| 놓음 — 40% 이상 | 열린 채로 자리를 잡습니다 |
| 열린 채 되돌려 밀기 | 트레이 폭의 25% 이상이면 닫힙니다 |
| 열린 채 줄 누르기 | **닫기만** 합니다 — 상세로 들어가지 않습니다(열어 둔 걸 못 보고 누르는 일이 많습니다) |
| 동작 누르기 | 트레이를 **먼저 닫고** 실행합니다(확인이 있으면 닫은 뒤 확인 창) |
| 열린 줄이 있는데 다른 줄 누르기 | 열린 줄을 **닫기만** 합니다 — 그 누름은 먹지 않습니다(다른 줄로 들어가지 않습니다). 열린 채 줄 누르기와 같은 까닭입니다 |
| 다른 줄을 끌기 · 목록 스크롤 | 열린 줄이 닫힙니다 — **한 번에 하나만** 열립니다 |
| 오른쪽으로 끌기 | 아무 일도 없습니다(RTL 은 반대) |
| 끝까지 밀기 | 동작을 실행하지 않습니다 — 트레이가 열릴 뿐입니다 |
| `Esc`(열린 트레이) | 닫고 초점을 줄로 옮깁니다 — 숨긴 트레이 버튼에 초점이 남지 않습니다 |
| 열림 · 닫힘 | 150ms(`motion-duration-d3`) 감속(`motion-ease-enter`). 끄는 동안은 손가락을 1:1 로 따라가며 모션이 없습니다. 모션 줄이기면 바로 |

## Do / Don't

### ✅ Do

- 동작은 1 ~ 3개, 파괴적인 것은 가장 안쪽에 하나만 둡니다.
- 트레이의 동작을 들어간 화면에도 모두 둡니다 — 같은 이름 · 같은 확인 창.
- 삭제는 트레이를 닫고 확인 창을 띄웁니다 — 제목 · 설명은 상세 경로와 같은 문구, 확인 버튼은 누른 동작의 라벨입니다.
- 배지는 동작의 글자색 + 반전 아이콘으로 그립니다 — 다크도 줄 바탕과 3:1 을 넘게 합니다.
- `Esc` 로 닫으면 초점을 줄로 옮깁니다.

### ❌ Don't

- 동작을 넷 이상 두거나 파괴적 동작을 여럿 두지 않습니다.
- 스와이프를 유일한 길로 두지 않습니다 — 키보드 · 스크린리더가 닿지 못합니다.
- 대신 길로 줄 끝 ⋮ 를 두지 않습니다 — 줄을 누르면 들어간 화면이 대신 길입니다.
- 누르는 즉시 삭제하거나 끝까지 밀면 실행하지 않습니다.
- 길에 따라 확인 문구를 다르게 쓰지 않습니다(상세 "계좌 삭제" · 밀기 "삭제").
- 다크에서 짙은 채움 배지(2.51) · 테두리 없는 중립 배지 · 파랑 주 동작 라벨을 쓰지 않습니다.
- 트레이 바탕을 칠하거나 데스크톱에서 트레이를 쓰지 않습니다.

## Specification

`swipe-actions.yaml` 의 규칙을 하나도 빼지 않고 조건마다 그립니다 — 웹 · 앱이 Swipe Actions 를 만들 때 이 값을 그대로 씁니다. 조건이 없는 `Base` 가 모든 조합에 걸리고, 뒤의 규칙이 앞의 같은 값을 덮습니다. 상태는 `enabled` 에서 바뀌는 값만 적었습니다.
