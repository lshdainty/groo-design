# Bottom Sheet

> 화면 아래에서 올라오는 모달입니다. 1280 미만에서 폼 · 상세 · 고르기를 띄우고, 같은 내용을 1280 이상에서는 [Dialog](dialog.md) 로 띄웁니다(한 부품이 폭으로 바꿉니다 — Responsive Dialog). 되돌릴 수 없는 확인은 [Alert Dialog](alert-dialog.md), 들어간 화면 머리 ⋮ 의 동작 목록은 [Menu Sheet](menu-sheet.md), 화면 높이의 90% 를 넘는 내용은 페이지입니다.

수치 원본은 [`bottom-sheet.yaml`](bottom-sheet.yaml)입니다.

[그림: 거래 추가 · 기간 · 거래 상세 — 라이트 · 다크](../../site/components/specs/bottom-sheet.tsx#hero)

### 직접 골라 보기

쓰임(입력 폼 · 고르기 · 조회) · 설명 · 바닥 버튼 수 · 손잡이를 고르면 스펙대로 그린 시트와 그 코드가 바뀝니다. 실제로 열고 닫을 수 있습니다.

## Properties

### 머리 · 본문 · 바닥

머리는 위 24 · 아래 16 이고 제목 22 / 30 · 700, 설명 16 / 22 입니다. 좌우는 안전 영역 + 화면 여백 24 입니다. 최대 폭 480 보다 넓은 화면에서 시트는 좌우 안전 영역을 뺀 자리의 가운데에 섭니다(옆 상태 칸이 있으면 화면 가운데가 아닙니다). 닫기 버튼이 있으면 제목 오른쪽을 64 비웁니다. 바닥은 위 12 · 아래 16 이고 그 아래에 안전 영역(홈 표시줄)을 더합니다. 바닥 버튼은 Button large 48 — 하나면 폭 전체, 둘이면 반씩 나눕니다. 확인을 여는 [삭제] 는 예외로 왼쪽에 `ghost` + `critical` 글자만큼 두고, 주 버튼이 남은 폭을 채웁니다([Button](button.md) 의 "모달 footer" 꼴).

[그림: 머리 · 본문 · 바닥의 여백](../../site/components/specs/bottom-sheet.tsx#layout)

### 머리 → 첫 칸

머리 아래는 본문 여백 그대로입니다 — 끝 흐림을 끄면 16, 켜면 위 흐림 20 을 더해 36. 끝 흐림을 끄면 그 20 도 함께 사라지므로, 첫 칸 위 값을 화면이 따로 더하지 않습니다. 예외는 **칸 이름 없이 바로 시작하는 제목 칸**(메모 · 일정 폼)입니다 — 칸 이름이 차지하던 자리를 대신해 위 12 · 아래 8 을 더합니다(28). 끝 흐림을 켠 시트에서는 위 20 이 이미 그 자리이므로 위 4 만 더합니다(40). 라벨 있는 칸 · 목록 · 값 줄로 시작하면 더하지 않습니다.

### 본문 끝 흐림

개수가 데이터에 따라 느는 목록 · 긴 글을 보여 주는 본문, 그리고 390 × 844 · 글자 100% · 보통 값에서 시트 90% 에 닿는 본문은 [Scroll Fog](scroll-fog.md) 를 겁니다(`scrollFog`) — 위 20 · 아래 80 이 늘 흐리고, 본문 안에 그만큼 여백을 둬 끝까지 내리면 흐림이 빈 여백 위에 놓입니다. 넘쳤는지 재서 켜고 끄지 않습니다 — 걸 본문인지는 내용의 종류로 정하고, 칸 두셋처럼 늘 들어맞는 본문과, 가장 나쁜 값에서만 넘치는 본문(프리셋 상세)에는 걸지 않습니다. 호출하는 화면이 정합니다 — 틀이 정하지 않습니다. 걸지 않아도 넘치면 본문은 스크롤됩니다. 1280 이상의 [Dialog](dialog.md) 에서도 같습니다.

### 손잡이

기본으로 없습니다 — 손잡이가 없어도 조회 · 고르기 시트는 아래로 끌어 닫힙니다. 시트가 절반 · 가득 같은 스냅 높이를 가질 때만 손잡이를 답니다(그때는 반드시). 손잡이를 누르면 다음(더 높은) 스냅 높이로 올라가고, 가장 높은 높이에서 누르면 닫힙니다. 손잡이에는 누름 색을 두지 않습니다.

[그림: 손잡이 — 스냅 높이를 둘 때만](../../site/components/specs/bottom-sheet.tsx#handle)

### 머리 ← — 두 단계 시트의 2단계

한 시트 안에서 두 단계로 나아가는 흐름(1단계 종류 고르기 → 2단계 폼)은 2단계 머리 왼쪽에 ← 를 답니다(`back`). 보이는 원 40 · 아이콘 24(꺾쇠 `chevron-left` — 페이지 머리 [Top Navigation](top-navigation.md) 의 ← 와 같은 모양) · 누르는 영역 44 이고, 아이콘이 화면 여백 24 에 오도록 원을 8 바깥에 둡니다. 세로는 제목 첫 줄 가운데입니다. 제목은 원 오른쪽 4 에서 시작합니다 — 화면 여백에서 36 들어갑니다. 원 바탕은 누를 때만 `bg-neutral-weak-pressed` 이고, 닫기 버튼과 달리 거리 축소는 없습니다. 쓰는 법은 Guidelines 의 "두 단계 시트의 머리 ←" 에 있습니다.

[표: 머리 ←](bottom-sheet.yaml#back)

### 머리 오른쪽 동작 — ⋮ 하나

들어간 시트(상세 · 수정)에서 그 항목의 동작이 여럿이면 머리 오른쪽에 ⋮ 하나를 둡니다(`headerAction`) — 누르면 [Menu Sheet](menu-sheet.md) 가 동작 목록을 엽니다. 자리는 닫기 버튼 왼쪽 사이 4 이고(닫기 버튼이 없으면 닫기 자리인 오른쪽 끝), 세로는 닫기 원과 가운데를 맞춥니다. 단추는 [Button](button.md) `ghost` 아이콘만(보이는 36 · 누르는 44)이고, 이름은 "{항목 이름} 더보기"("거래 더보기")입니다. 제목은 단추 자리를 비운 남은 폭에서 줄을 바꾸고 단추와 겹치지 않습니다. 초점 차례는 제목 → 동작 → 닫기입니다(← 가 있으면 맨 앞). 머리 동작은 **하나만** 둡니다 — 둘째 동작을 머리에 나란히 늘어놓지 않고 ⋮ 의 메뉴에 넣습니다(웹 `headerAction` · 앱 `PBottomSheetContent.headerAction`).

## Guidelines

### 시트에 띄우는 것

1280 미만에서 지금 화면을 떠나지 않고 할 일 — 입력 폼(거래 추가 · 수정), 고르기(기간 · 정렬 · 날짜 — Input Button 의 시트), 조회(거래 상세)를 띄웁니다. 같은 내용은 1280 이상에서 [Dialog](dialog.md) 로 뜹니다 — 머리 · 본문 · 바닥은 같고 표면만 바뀝니다. 되돌릴 수 없는 확인은 [Alert Dialog](alert-dialog.md), 들어간 화면 머리 ⋮ 의 동작 목록(수정 · 복사 · 삭제)은 [Menu Sheet](menu-sheet.md) 입니다 — 목록 줄에는 ⋮ 를 두지 않습니다([Menu](menu.md) 의 "줄의 동작").

어느 떠 있는 표면을 쓸지 — 시트 · 대화상자 · 확인창 · 팝오버 · 메뉴 · 메뉴 시트 · 옆 패널을 한눈에 견준 "상황 → 고를 것" 표는 DESIGN.md Components 의 "시트 · 대화상자 · 확인창 · 팝오버" 한 벌입니다. Desk 데스크톱 벨의 알림 목록도 그 표에 있습니다(768 ~ 1279 시트 · 1280 이상 [Popover](popover.md)).

쌓임 순서는 [specs/z-index.md](../z-index.md) 의 L2(딤 `z-modal` 100 · 시트 `z-modal-content` 101)입니다 — 그 위에 Popover(L3) · Alert Dialog(L5)가 뜹니다.

[그림: 쓰임 — 폼 · 고르기 · 조회는 시트 · 확인은 Alert Dialog](../../site/components/specs/bottom-sheet.tsx#role-guide)

### 90% 를 넘으면 페이지

시트는 내용만큼 높고 화면 높이의 90% 를 넘지 않습니다. 처음부터 길게 짠 내용은 시트를 90% 로 늘려 버티지 않고 페이지로 옮깁니다 — 뒤로 가기 · 주소가 자연스럽게 따라옵니다. 다만 보통은 들어맞는 시트가 작은 화면 · 큰 글자 · 키보드로 넘치는 것은 페이지로 옮길 일이 아닙니다 — 본문만 스크롤하고 끝을 흐립니다.

| 상황 | 쓰는 것 | 주의 |
|---|---|---|
| 처음부터 길게 짠 내용 — 카테고리 전체 관리 · 단계가 셋 넘는 흐름 · 끝없는 목록 | 페이지 | 주소 · 뒤로 가기가 따라옵니다. 시트를 90% 로 늘려 버티지 않습니다 |
| 보통은 들어맞는데 작은 화면(360 × 568) · 큰 글자 · 키보드로 넘친 것 | Bottom Sheet 그대로 — 본문만 스크롤 + 끝 흐림 | 머리 · 바닥은 그대로 보입니다. 거는 기준은 위 "본문 끝 흐림" 입니다 |
| 개수가 데이터에 따라 느는 목록(알림 · 검색 결과) | 시트 + 끝 흐림 — 길어질 수 있으면 페이지를 먼저 생각 | 시트에 둔다면 Scroll Fog 는 넘쳤는지 재지 않고 늘 겁니다 |
| **예외** — 칸이 줄로 이어지는 입력 폼(거래 추가 2단계 · 수정 · 반복 거래 · 프리셋 · 일정) | Bottom Sheet 그대로 — 처음부터 90% 를 넘어도 본문만 스크롤 + 끝 흐림 | 머리 · 바닥(저장)은 그대로 보입니다. 폼을 연 목록 위에서 채우고 닫으면 바로 그 목록입니다 |
| **예외** — 조회 시트 안에서 이어지는 단계(거래 상세 → 수정 → 나눈 내역) | 같은 시트 | 위 "두 단계 시트의 머리 ←" 로 한 단계씩 돌아갑니다 |

**긴 입력 폼은 시트에 둡니다(예외).** 위 "처음부터 길면 페이지" 는 목록 · 관리 화면 · 끝없는 흐름의 규칙입니다. 칸이 줄로 이어지는 입력 폼은 처음부터 화면을 넘어도(360 × 760 에서 반복 거래 시트 684 · 본문 538 안에 864) 시트로 두고 본문만 스크롤하며 끝을 흐립니다. 조회 시트에서 이어지는 수정 · 나눈 내역도 같은 시트 안의 단계입니다. 폼을 연 목록을 떠나지 않아, 채우고 닫으면 바로 그 목록으로 돌아오기 때문입니다.

[그림: 높이 — 내용만큼 · 90% 를 넘는 시트](../../site/components/specs/bottom-sheet.tsx#height-guide)

### 두 단계 시트의 머리 ←

종류를 먼저 고르고(1단계) 그 종류의 폼을 쓰는(2단계) 흐름은 한 시트 안에서 단계를 바꿉니다 — 2단계 머리 왼쪽 ← 가 1단계로 한 단계 되돌립니다(자산 추가 — "무엇을 추가할까요?" → "입출금 추가"). 저장 전 본인 확인(가린 금액 보기 인증)처럼 시트 안에 끼어든 한 단계도 같은 ← 로 앞 단계에 돌아갑니다(저장하지 않습니다). 수정처럼 1단계가 없는 시트에는 ← 가 없습니다. 오른쪽 위 닫기 버튼은 그대로 두고, ← 는 시트를 닫지 않습니다.

- **쓴 값이 있으면 묻고 버립니다** — 2단계에서 쓴 값이 있으면 ← 를 누를 때 "작성한 내용이 사라져요" 를 먼저 묻고, [나가기] 면 1단계로 돌아가며 그 값을 버립니다. 종류가 바뀌면 폼의 칸이 달라지므로 앞 종류에서 쓴 값을 들고 가지 않습니다. 쓴 값이 없으면 묻지 않고 돌아갑니다.
- **종류는 1단계에서만 바꿉니다** — 2단계 폼 맨 위에 "종류" 고르기 칸을 두지 않습니다. 다른 묶음(계좌 → 카드)으로 바꾸면 칸이 달라져 쓴 값을 어떻게 할지 따로 정해야 하고 폼이 칸 하나만큼 길어지기 때문입니다.
- **같은 시트 안의 단계에만** — 단계가 셋을 넘는 흐름은 시트가 아니라 페이지입니다("90% 를 넘으면 페이지" 표). 페이지의 ← 는 [Top Navigation](top-navigation.md) 의 것이고, 이 ← 는 시트 머리에서 한 단계만 되돌립니다.
- **초점 · 뒤로 가기** — 다음 단계로 들어가면 초점은 새 단계의 제목으로 갑니다. ← 로 돌아오면 앞 단계에서 누른 줄로 돌아갑니다. 기기 뒤로 가기(안드로이드 · 브라우저)는 한 단계 뒤입니다 — 첫 단계에서만 시트를 닫습니다.
- **만들기 · 지우기가 끝나면** — 줄 목록(1단계)에서 대상을 골라 2단계에서 연결 · 해제하는 흐름(증권사 연동)은, 연결(만들기)이 성공하면 그 대상의 조회 단계에 머물고 [Snackbar](snackbar.md) 로 알립니다. 해제(지우기)가 성공하면 첫 단계로 돌아가고 스낵바로 알립니다 — 지운 대상의 단계에 남지 않습니다. 웹 · 앱이 같습니다.
- **1280 이상의 대화상자도 같습니다** — 같은 흐름을 [Dialog](dialog.md) 로 띄우면 머리 왼쪽에 같은 값의 ← 를 답니다.

### 입력 폼은 실수로 닫히지 않게

입력 폼 시트는 바깥을 눌러도, 아래로 끌어도 닫히지 않습니다 — 손잡이를 달지 않습니다. 위 닫기 버튼 · 뒤로 가기 · `Esc` 로 닫고, 바뀐 값이 있으면 닫기 전에 "작성한 내용이 사라져요" 를 묻습니다([Field](field.md) 의 규칙). 조회 · 고르기 시트는 바깥 누르기 · 끌어내리기로 닫힙니다.

- **휠 시트도 끌기 · 바깥으로 닫지 않습니다** — 시각 · 날짜 휠([Time Picker](time-picker.md) · [Date Picker](date-picker.md) 의 휠)을 위아래로 굴리는 손이 시트 끌기로 읽혀 시트가 내려가 버리기 때문입니다. 휠이 든 시트는 `dismissible={false}`(앱도 같은 이름의 플래그)입니다 — 끌어내리기 · 바깥 누르기는 아무 일도 하지 않고 시트 몸통도 손가락을 따라 내려가지 않습니다. 위 닫기 버튼 · 바닥 [완료] · `Esc` · 뒤로 가기로만 닫습니다. 바뀐 값을 묻지는 않습니다(완료 전 휠 값은 버립니다 — 고르기 시트 그대로). 플래그 기본값은 참(끌기 · 바깥 누르기로 닫힘)이고, 입력 폼은 늘 끈 것과 같습니다.

- **저장 중에는 닫히지 않습니다** — 바닥 [저장] 이 로딩인 동안은 닫기 버튼 · 뒤로 가기 · 바깥 · `Esc` · 끌어내리기 · 머리 ← 를 모두 무시합니다(닫기 버튼 모양은 그대로). 쓰기가 실패하면 폼 맨 위 [Callout](callout.md) 로 알리므로 그 자리가 남아 있어야 합니다. 확인창([Alert Dialog](alert-dialog.md))은 해당 없습니다 — 닫고 스낵바로 알립니다.
- **한 번만 보이는 비밀은 닫기 전에 묻습니다** — 발급한 토큰 원문처럼 닫으면 다시 볼 수 없는 값을 보이는 단계에서, 복사하지 않고 닫으려 하면 한 번 묻습니다 — 제목 "토큰을 복사하지 않았어요" · 설명 "닫으면 이 토큰을 다시 볼 수 없어요." · [취소] [닫기]. 복사했으면 묻지 않습니다.

[그림: 닫기 — 입력 폼은 바깥 · 끌기로 닫히지 않습니다 · 조회는 닫힙니다](../../site/components/specs/bottom-sheet.tsx#dismiss-guide)

### 닫기 버튼과 바닥 버튼

시트의 입력 폼은 위 닫기 버튼 + 바닥 [저장] 하나입니다 — 바닥에 [취소] 를 따로 두지 않습니다(닫기 버튼과 취소를 함께 두지 않습니다). 조회 · 고르기도 위 닫기 버튼이고, 바닥 버튼은 고른 것을 넣을 때("완료" · "적용")만 둡니다. 둘을 나란히 둘 때는 보조(초기화)를 왼쪽, 주 버튼을 오른쪽에 반씩 둡니다.

목록 줄을 눌러 들어간 시트(상세 · 수정)에서 동작이 삭제 하나뿐이면 바닥 왼쪽에 [삭제](`ghost` + `critical`)를 둡니다 — 주 버튼([저장] · [수정])이 있으면 그 버튼이 남은 폭을 채우고, 없는 조회 시트는 [삭제] 하나만 왼쪽에 섭니다. 입력 폼 시트(태그 · 거래 수정)도 같습니다 — 바닥 왼쪽 [삭제] + 오른쪽 [저장] 으로, [Button](button.md) 의 모달 footer("삭제는 왼쪽 ghost + critical, 저장은 오른쪽")와 같은 꼴입니다. 바닥의 왼쪽 자리는 이 [삭제] 의 자리입니다 — 다른 버튼을 두지 않습니다(웹 · 레시피는 `BottomSheetFooter` 안에 [삭제] 를 먼저 둡니다).

**바닥을 직접 짜는 자리** — 바닥 버튼 하나 · 둘로 그릴 수 없는 바닥은 바닥 칸을 통째로 받는 자리로 짭니다 — 앱 `PBottomSheetContent.footerRow`, 웹 · 레시피 `BottomSheetFooter` 의 자식. 이 자리는 [삭제] 전용으로 좁히지 않습니다(`deleteAction` 같은 이름으로 바꾸지 않습니다) — 바닥 왼쪽 [삭제] + 주 버튼 말고도 두 단계 폼의 [이전] · [만들기], 저장 바로 위 합계 · 남은 금액 · 오류 한 줄 + [저장] 이 이 자리를 쓰고(더치페이 · 거래 나누기), 웹 `BottomSheetFooter` 도 자식을 가리지 않습니다. 지킬 것은 자리가 아니라 내용 규칙입니다 — 여백은 바닥과 같고(위 12 · 좌우 24 · 아래 16), 버튼은 Button large 48 이고, 왼쪽 자리는 [삭제] 뿐입니다. 동작이 여럿이면 바닥이 아니라 머리 ⋮(위 "머리 오른쪽 동작") → [Menu Sheet](menu-sheet.md) 입니다. 목록 줄에는 ⋮ 를 두지 않습니다([Menu](menu.md) 의 "줄의 동작").

[그림: 바닥 왼쪽 삭제 — 상세(삭제 · 수정) · 수정이 없는 조회(삭제 하나)](../../site/components/specs/bottom-sheet.tsx#delete-guide)

[그림: 버튼 — 폼은 위 닫기 + 바닥 저장 · 닫기와 취소를 함께](../../site/components/specs/bottom-sheet.tsx#buttons-guide)

### 글

제목은 무엇을 하는 시트인지 말합니다 — "거래 추가" · "기간". 설명은 덧붙일 말이 있을 때만 한 문장으로 씁니다(해요체 · 마침표). 버튼은 동작 이름("저장" · "적용")입니다 — "확인" 으로 뭉뚱그리지 않습니다.

## 코드

레시피 `recipes/shadcn/components/ui/bottom-sheet.tsx` 를 씁니다(vaul 위). 폼 · 상세는 1280 에서 Dialog 와 바뀌는 `ResponsiveDialog`([Dialog](dialog.md) 의 코드)로 짜고, 늘 시트인 자리(Input Button 의 시트 · 고르기)만 `BottomSheet` 를 바로 씁니다. 본문에 [List](list.md) 를 바로 두면 줄이 제 좌우 여백(24)을 가지므로 본문 좌우 여백을 뺍니다(`className="px-0"`). `BottomSheetFooter` 는 Button 의 짝 버튼 부품 `ResponsivePair` 입니다 — 버튼 둘은 반씩이고, 한 라벨이 반 폭을 넘으면 세로로 쌓고 주 버튼(뒤)이 위로 갑니다. 아래 미리보기는 스펙 값으로 그린 모습입니다.

바닥 왼쪽 [삭제] 는 글자만큼 둡니다 — 버튼에 `data-fit="content"` 를 주면 `ResponsivePair` 가 반 폭 바탕을 주지 않고, 남은 폭을 주 버튼이 채웁니다(`<Button variant="ghost" ghostColor="critical" data-fit="content">삭제</Button>`).

## Behavior

| 인터랙션 | 동작 |
|---|---|
| 열기 | 300ms 로 아래에서 올라옵니다. 처음 초점은 시트(본문 위)에 갑니다 — 내용이 첫 자리를 정하면(검색 시트의 검색칸 · 아이콘 고르기의 고른 칸) 시트가 그리로 넘겨줍니다(`onOpenAutoFocus`, 열린 뒤 다시 옮기지 않습니다). |
| 닫기 버튼 · `Esc` · 뒤로 가기 | 닫습니다. 입력 폼에 바뀐 값이 있으면 먼저 묻습니다. 두 단계 시트의 2단계에서 뒤로 가기는 한 단계 뒤입니다(첫 단계에서만 닫습니다). 저장 중에는 모두 무시합니다. |
| 바깥(딤) 누르기 | 조회 · 고르기 시트는 닫습니다. **입력 폼 · 휠 시트(`dismissible={false}`)는 무시합니다.** |
| 아래로 끌기 | 조회 · 고르기 시트는 놓을 때 빠르게(0.4px/ms 넘게) 끌었거나 높이의 25% 이상 내려왔으면 닫고, 아니면 제자리로 돌아갑니다. 열린 뒤 0.5초는 끌리지 않습니다. 본문을 스크롤하는 중이면 끌지 않습니다. **입력 폼 · 휠 시트는 끌리지 않습니다**(시트 몸통이 손가락을 따라가지도 않습니다). |
| 손잡이 누르기 | 다음(더 높은) 스냅 높이로 올라갑니다 — 가장 높은 높이에서 누르면 닫습니다. |
| 머리 ⋮ 누르기 | 그 항목의 동작 목록 [Menu Sheet](menu-sheet.md) 를 엽니다(시트 위에 뜹니다). 고른 동작이 확인을 열면 메뉴 시트가 닫힌 뒤 엽니다. |
| 머리 ← 누르기 | 두 단계 시트의 2단계 — 같은 시트 안에서 1단계로 한 단계 되돌립니다(시트는 닫지 않습니다). 2단계에 쓴 값이 있으면 먼저 "작성한 내용이 사라져요" 를 묻고, 돌아가면 그 값을 버립니다. |
| 글자 크기 설정 | 제목 · 설명 · 본문 · 바닥 버튼의 글이 커집니다. 시트 폭은 그대로이고 줄을 바꿔 높이가 늘어나며, 넘치면 본문이 스크롤합니다. 닫기 원 · ← 원 · ⋮ · 손잡이는 크기를 그대로 두고, 닫기 · ← · ⋮ 는 제목 첫 줄 가운데를 따라 내려갑니다 |
| 닫힌 뒤 | 200ms 로 내려가고, 초점은 연 자리(트리거)로 돌아갑니다. |
| 열린 동안 | 뒤 화면을 보조 기술에서 숨기고 스크롤을 잠급니다. 초점은 시트 안을 돕니다. |
| 키보드(폰) | 입력에 초점이 가면 시트가 키보드(브라우저 입력 도구줄 포함) 위로 올라가고, 초점 칸 전체가 바닥 위에 보이게 본문을 스크롤합니다(Layout 의 "화면 키보드"). |
| 키보드가 뜬 채 닫기(폰 웹) | 닫는 모든 길(닫기 버튼 · `Esc` · 딤 · 뒤로 가기 · 끌기 · 묻는 창의 [나가기])에서 먼저 입력 칸의 초점을 빼 키보드를 내리고, 보이는 높이가 키보드 없는 높이로 돌아온 뒤(길어도 400ms) 닫습니다 — 그동안 시트는 키보드를 따라 내려옵니다. 키보드가 내려가는 동안 iOS 사파리가 새 터치를 문서에 넘기지 않아, 닫히자마자 누른 탭이 사라지기 때문입니다. 키보드가 뜬 때 손가락으로 누른 닫기 버튼은 뗄 때 닫습니다(사파리가 click 을 버리는 때가 있습니다). 닫힘 200ms 는 그대로이고, 키보드가 없으면 기다리지 않습니다. |

## Do / Don't

### ✅ Do

- 1280 미만의 폼 · 상세 · 고르기를 시트로 — 1280 이상은 같은 내용을 Dialog 로.
- 입력 폼은 바깥 · 끌기로 닫지 않고, 바뀐 값이 있으면 닫기 전에 묻습니다.
- 휠이 든 시트(시각 · 날짜 휠)는 `dismissible={false}` — 굴리다 시트가 내려가지 않게.
- 시트의 입력 폼은 위 닫기 + 바닥 저장 하나.
- 들어간 시트의 동작이 삭제 하나면 바닥 왼쪽 [삭제] `ghost` + `critical`.
- 처음부터 화면 높이의 90% 를 넘게 짠 내용은 페이지로 — 작은 화면 · 큰 글자로 넘친 것은 본문만 스크롤(끝 흐림은 위 "본문 끝 흐림" 기준). 칸이 줄로 이어지는 입력 폼은 예외 — 길어도 시트 + 본문 스크롤 + 끝 흐림.
- 한 시트 안 두 단계 흐름의 2단계는 머리 왼쪽 ← 로 1단계에 돌아갑니다 — 쓴 값이 있으면 묻고 버리고, 닫기 버튼은 그대로 둡니다.

### ❌ Don't

- 닫기 버튼과 바닥 취소를 함께.
- 스냅 높이가 없는데 손잡이를 장식으로.
- 되돌릴 수 없는 확인을 시트로(Alert Dialog).
- 처음부터 화면을 넘게 짠 내용(목록 · 관리 화면 · 셋 넘는 단계)을 시트에 — 시트를 90% 로 늘려 버티기(페이지). 입력 폼은 예외(위 "긴 입력 폼은 시트에 둔다").
- 입력 폼 시트 위에 또 입력 폼 시트를 겹치기 — 그 위에는 고르기 시트(Input Button)와 확인창만 뜹니다.
- 2단계 폼 맨 위에 "종류" 칸을 둬 단계를 건너 종류를 바꾸기 · 단계가 셋을 넘는 흐름을 시트 머리 ← 로 잇기(페이지) · ← 를 두고 닫기 버튼을 걷기.
